# پروژه مدیریت موجودی چندسازمانی

این پروژه با Laravel 12 و MySQL نوشته شده و کارش مدیریت موجودی انبارها، ثبت ورود و خروج کالا، انتقال کالا بین انبارها و جدا نگه داشتن اطلاعات سازمان‌هاست. هر سازمان فقط به اطلاعات خودش دسترسی داره.

## راه‌اندازی پروژه

اول پروژه رو دریافت و وابستگی‌ها رو نصب کنید:

```bash
git clone https://github.com/Saberqadimi/multitenance.git
cd multitenance
composer install
```

بعد فایل `.env.example` رو به `.env` کپی کنید، اطلاعات اتصال به MySQL رو تنظیم کنید و دیتابیس `multitenance` رو بسازید. سپس دستورات زیر رو اجرا کنید:

```bash
php artisan key:generate
php artisan migrate
php artisan db:seed
php artisan serve
```

با اجرای `db:seed`، اطلاعات نمونه شامل دو سازمان `digikala` و `divar` به‌همراه محصولات و انبارهاشون ساخته می‌شه.

آدرس اجرای پروژه:

`http://127.0.0.1:8000`

## ۱. اجرای تست‌های خودکار

برای اجرای تست‌ها کافیه دستور زیر رو بزنید:

```bash
php artisan test
```

تست‌های فعلی ورود و خروج کالا، انتقال بین انبارها، جلوگیری از منفی شدن موجودی و دسترسی نداشتن یک سازمان به محصولات و انبارهای سازمان دیگه رو بررسی می‌کنن.

آخرین نتیجه تست‌ها: **۹ تست موفق و ۲۴ Assertion**.

## ۲. تست هم‌زمانی موجودی

برای بررسی اینکه درخواست‌های هم‌زمان باعث منفی شدن موجودی نمی‌شن، اسکریپت زیر رو اجرا کنید:

```bash
php artisan db:seed --class=ConcurrencyTestSeeder
php scripts/run_concurrency_test.php
```

این تست ۱۰۰ درخواست خروج رو به‌صورت هم‌زمان و با موجودی اولیه ۵۰ اجرا می‌کنه. نتیجه مورد انتظار، ۵۰ درخواست موفق، ۵۰ درخواست ردشده و موجودی نهایی صفره. در صورت موفقیت، خروجی `PASS` نمایش داده می‌شه.

**نکته:** این اسکریپت به دیتابیس جداگانه `multitenance_concurrency_test` وصل می‌شه و نیازی به اجرای `php artisan serve` نداره. قبل از اجرا، مطمئن بشید دیتابیس آزمایشی وجود داره و تنظیمات اتصال درست هستن.

## ۳. تست APIها با Postman

برای تست APIها می‌تونید از Postman Collection ضمیمه‌شده استفاده کنید.

آدرس پایه:

`http://127.0.0.1:8000/api`

هدرهای مورد نیاز:

```http
Accept: application/json
X-Tenant: digikala
```

مقدار `X-Tenant` باید با زیر‌دامنه یکی از سازمان‌های موجود در دیتابیس مطابقت داشته باشه. سازمان‌های نمونه با اجرای Seeder اصلی ساخته می‌شن.

سه endpoint اصلی پروژه:

| متد و مسیر | کاربرد |
|---|---|
| `POST /api/stock-movements` | ثبت ورود، خروج یا انتقال کالا |
| `GET /api/stock-levels` | دریافت موجودی انبارها با فیلتر و صفحه‌بندی |
| `GET /api/products/{sku}/history` | مشاهده تاریخچه گردش‌های یک محصول |

برای فیلتر موجودی می‌تونید از `filter[product_id]` و `filter[warehouse_id]` استفاده کنید. پارامترهای `per_page` و `page` هم برای صفحه‌بندی هستن.

نمونه بدنه درخواست برای خروج کالا:

```json
{
  "product_id": 1,
  "warehouse_id": 1,
  "type": "out",
  "quantity": 1,
  "reference": "order-101"
}
```

مقدار `type` می‌تونه `in`، `out` یا `transfer` باشه. برای انتقال هم باید اطلاعات انبار مبدأ و مقصد رو طبق ساختار درخواست در فیلد `meta` ارسال کنید.

کدهای پاسخ مهم:

- `201`: درخواست با موفقیت ثبت شده
- `422`: خطای اعتبارسنجی یا کافی نبودن موجودی
- `400`: هدر سازمان نامعتبره
- `404`: سازمان موردنظر پیدا نشده

## ۴. بررسی زمان پاسخ API موجودی

برای بررسی زمان پاسخ endpoint موجودی، اول سرور رو اجرا کنید و بعد دستور زیر رو در ترمینال ویندوز اجرا کنید:

```powershell
curl.exe -s -o NUL -w "Total: %{time_total}s | TTFB: %{time_starttransfer}s`n" "http://127.0.0.1:8000/api/stock-levels?per_page=100" -H "X-Tenant: performance-test" -H "Accept: application/json"
```

- `Total`: زمان کل دریافت پاسخ
- `TTFB`: زمان دریافت اولین بخش پاسخ

## ۵. بررسی مغایرت موجودی

برای بررسی مغایرت بین موجودی ثبت‌شده و موجودی محاسبه‌شده از روی گردش‌ها، دستور زیر رو اجرا کنید:

```bash
php artisan inventory:reconcile digikala
```

در صورت پشتیبانی دستور، می‌تونید به‌جای `digikala` شناسه عددی سازمان رو هم وارد کنید.

این دستور موجودی هر محصول در هر انبار رو با مجموع گردش‌ها مقایسه می‌کنه، مغایرت‌ها رو گزارش می‌ده و در لاگ ثبت می‌کنه. موجودی‌ها به‌صورت خودکار تغییر نمی‌کنن.
